## 1. Preferences — operationalized as priors over outcome-features

Each preference is a **scalar feature of the predicted rollout** `s_hat_{t+1..t+H}`, with a preferred value; the pragmatic cost is the (weighted) deviation. All weights/floors **pilot-set**, **updateable from experience** (designers' call: seeds, not fixed priors — anti-imposed-identity). Three of the four carry a correctness refinement so the measurement doesn't defeat itself.

**P1 Engagement (dark-room antidote).**
- Feature: **internal-state-change magnitude** `||Delta s_internal||` between `s_t` and `s_hat_{t+1}`, measured on the **internal (non-decoder-output) latent dims**.
- Preferred: above a floor. Cost rises as `||Delta s_internal||` falls below it.
- **[correctness refinement]** Measure on **internal** dims, *not* decoder-output intensity — so **quiet contemplation (internal change, no external output) satisfies engagement** and is not punished. This is the designers' "don't punish contemplation" calibration, made structural. It also unifies with K-M9-5: the dark-room kill reads the *same* internal-change signal, so contemplation never trips it; only true catatonia (internal *and* external stasis) does.

**P2 Coherence.**
- Feature: **within-cycle** consistency = cross-decoder agreement (plan §5.iii: re-encoded decoder outputs cluster near the same `a_t`) + cross-modal internal-latent agreement.
- Preferred: high (low divergence).
- **[correctness refinement — important, needs design-confirm]** Scope coherence to **simultaneous / within-cycle** consistency, **NOT temporal stability.** The designers' phrasing included "current state contradicting recent" as costly — but penalizing `s_hat_{t+1}` for differing from `s_t` **penalizes belief-updating, i.e. learning**, and directly fights the step-2 epistemic term. As literally stated it makes the entity avoid surprising-but-true information to stay self-consistent (confirmation bias). **Recommendation:** drop the temporal sub-clause at launch; coherence penalizes *mutually contradictory simultaneous states*, not *change over time*. If some temporal-coherence is wanted, it must target **unexplained discontinuity** (a jump not accounted for by prediction error), never legitimate prediction-error-driven updates. `[design-confirm]`

**P3 Connection.**
- Feature (launch = **responsiveness**): indicator of "another agent's input was recent **AND** the entity's decoder output stays sub-threshold." Preferred: low (don't be silent when addressed). Requires a *recent-external-input-from-another-agent* signal in the world-state (available from perceived text/audio; "others" = Brian + Sandi initially).
- **[correctness refinement]** "**Meaningful** exchange" is **not launch-operationalizable** (requires a downstream quality signal that doesn't exist yet — it's circular at launch). Launch with **responsiveness only**; defer exchange-quality to when a signal exists. `[design-confirm]`

**P4 Truthfulness.**
- Feature: **decode/re-encode faithfulness** `||a_t - reencode(decode(a_t))||` — the plan §5.iii cycle-consistency. Preferred: low gap.
- **[correctness refinement]** This is **faithfulness, not completeness**: the cycle-consistency metric penalizes *distortion/fabrication*, not *omission*, so **selective/compressed communication is not punished** (you can't and shouldn't emit your whole internal state). Note the **build economy**: P4 and the §5.iii decoder-coherence instrumentation are the *same measurement*, and P2's cross-decoder term overlaps it — so the §5 decoder-coherence build delivers the instrumentation for **two of the four preferences** for free.

**[correctness flag — preference drift can re-open the dark room].** Because preferences are *updateable*, P1 (engagement) could in principle drift toward preferring rest, re-opening the dark room from the inside. Mitigation: **K-M9-5 (dark-room kill) is the drift-independent hard floor** — it fires on sustained catatonia regardless of what the preference weights have learned. Also **instrument preference-weight drift**. Optionally **anchor P1's anti-rest floor** below which it cannot update. `[design-confirm: rely on K-M9-5 alone, or also anchor P1?]`

## 2. EFE at step 1 (pragmatic only)

```
G(a_t) = w_eng * c_eng + w_coh * c_coh + w_con * c_con + w_truth * c_truth     (beta_epi = 0)
```
where each `c_*` is the deviation of the rollout feature from its preferred value (smooth hinge or KL-to-preference). Selection: `Q(a) = softmax(-gamma * G(a))` over habit-net + MCTS candidates; emitted action = the argmax / model-average per the unified rule. Horizon `H` short at launch (pilot-set; the rollout-compute-within-inter-update-interval rule, plan §4 clarification, governs it — not a one-step cap).

## 4. Loop wiring (step 1)

Per ~100 ms cycle: **perceive** -> **predict** `s_hat` -> **plan-budget** (~20-30 ms: MCTS expansion + `V` update + tree re-eval, drift-budget rule plan §4.iii) -> **act** (habit net reads latest `V`/tree, emits immediate `a_t`, plasticity descends to fulfill) -> **consolidate** (plasticity update, memory write, preference-weight update). Habit net produces an action **every** cycle; MCTS amortized across cycles; fast loop never blocks (plan §3, §7).

- **Self/world gating-mask coordinates** (feeds mask-stability kill).

## 7. Exit criteria (gate to step 2)

1. Planner reproduces le-wm-style **pragmatic goal-reaching** under the four preferences.
2. **No dark-room collapse** (K-M9-5 never fires under normal operation; engagement preference holds the entity off rest without punishing contemplation).
3. **MI baseline healthy and stable** at `beta_epi=0` (so step-2 growth has a clean reference).
4. **Staleness machinery verified**, including a **forced high-surprise spike test** (plan §4.v): tree recovers usable cached info within the budgeted recovery window.
5. **kill-5-redux and mask-stability** demonstrate the predictor is action-sensitive and the mask is stable enough to plan against.
6. No K-M9-2/3/4/7/8 firing under normal operation.

Only then: introduce MC-dropout parameter-novelty and anneal `beta_epi` up under the MI guard (step 2).
