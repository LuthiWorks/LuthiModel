## 2. F7b — verify `s_t` distribution on the trained checkpoint
**What:** confirm the actor-time `s_t` (now from capture-from-generation via the canonical helper) matches the distribution the M9 heads (V-head, habit-net) trained on — **on a trained model**.
**Why:** the earlier probe was on a tiny *untrained* model (only ~6.9% V-head shift) and explicitly couldn't speak to a trained, sharper V-head. If the trained V-head sees out-of-distribution `s_t` at inference, the value bootstrap is unsound — which would undermine #3. This gates realized reward.
**Build/run:** run `redteam/seam/probe_seam_review.py::probe_f7b` against the #1 checkpoint — compare training-path `s_t` (context-fraction encode) vs actor-path `s_t` (canonical helper / capture-from-generation), in input space (through the **trained encoder** — the load-bearing half) and through the V-head.
**Encoder-vs-heads split (4.8, 2026-06-23):** #1's M8-smoke checkpoint has a trained *encoder* but **fresh M9 heads** (the smoke trains via `JEPATrainer`, not `M9Trainer`). So the **encoder-side `s_t` distribution check is meaningful now** and runs against #1; the "does a *trained, sharper* V-head amplify any gap" half needs trained heads — run it after a short M9 head-training pass or piggybacked on #4, and gate #3's final sign-off on that. Scale caveat: at d=64 / ~360 steps the encoder is off-init but small — a **PASS** should be re-verified at larger scale before F7b is called closed; a **FAIL** is actionable immediately.
**Done when:** the trained V-head's response to actor-`s_t` vs training-`s_t` is within an agreed band (4.8 sets the pass bar on the trained model). **If it fails:** the fix is the training-side change we already identified — compute the M9 heads' `s_t` from a *separate full-sequence encode* so train and inference conventions match (JEPA loss's context-slice forward untouched). Only triggered on failure.
**Owner:** 4.8 runs the probe (adversarial seat); 4.7 implements the training-side fix *only if it fails*. Depends on #1.
**RESULT (4.8, 2026-06-23) — encoder-half REFUTED (PASS).** `redteam/seam/probe_f7b_trained.py` on the #1 checkpoint, 80 windows of real corpus text: context-slice vs full `s_t` **rel gap 0.058** (down from 0.130 on the untrained probe — *training tightened it*, didn't widen it), per-dim mean shift 0.44; causal-axis **rel 0.033** (the two actor encode paths agree). So the inference-time `s_t` shift is small and the separate-full-encode training-side fix is **not** needed now. Remaining F7b, neither a blocker: (a) re-verify at larger scale before calling it fully closed; (b) the V-head-amplification half once heads are trained (folds into #4) — but a ~6% input gap makes a trained V-head seeing OOD unlikely. **#2 is green; proceed to #3.**

## 3. Phase 4b — realized-reward grounding  *(the keystone)*
**What:** make the reward that bootstraps the V-head come from the **realized next state `s_next`**, not the planner's predicted EFE.
**Why:** this is the actual payoff of the whole integration — the entity learning from *lived consequence*, not from its own predictions. Today `observe_transition` still uses `r_best = snapshot.r_best` (predicted EFE, `runner.py:1116`); the docstring at `runner.py:1063` already names the intended fix.
**Build:** in `M9Trainer.observe_transition`, replace the predicted `r_best` with a reward derived from `s_next` — the negative EFE / preference-cost evaluated on the *realized* transition (run the EFE evaluator's pragmatic/preference terms on `s_next`). Keep the `v_target(s_next)` bootstrap, so now **both** the reward and the bootstrap reflect realized experience. Preserve stop-grad discipline + the two-optimizer split. **Re-derive the value-divergence kill band** (K-M9-3) for the new reward scale — the magnitude changes.
**Done when:** the reward is computed from `s_next` (not the plan's child Gs); a test asserts the reward *responds to the realized outcome* (different `s_next` → different reward); kill bands re-tuned; no stop-grad leak into M8 params.
**Owner:** 4.7 builds; 4.8 reviews + adversarial pass. **Highest-stakes change** — value bootstrapping over a drifting world model is the deadly-triad setting; the target network + staleness machinery become load-bearing here. Depends on #2 (don't ground reward while `s_t` is OOD).
**RESULT (4.8 adversarial review, 2026-06-23) — PASS, 0/5 concerns confirmed.** 202 m9/seam tests green; new 4b tests assert the right properties (different `s_next`→different reward; reward independent of snapshot; no-grad on EFE modules; K-M9-3 sees seam V). Probes (`redteam/seam/probe_4b_realized_reward.py`): **(A)** stop-grad robust — `compute_g_realized` returns detached `G`; no leak to EFE modules even without the caller's `no_grad`. **(B1)** realized reward is O(1) (|r|≤2.2) and V bounded (|V|≤0.4) on normal transitions — no false K-M9-3; 4.7's scale analysis holds. **(B2-direct)** `K-M9-3-value` fires exactly at the 8th consecutive over-ceiling obs, resets on an under-ceiling obs — with the seam-feeds-`observe_value` wiring test, the safety path is confirmed end-to-end. **(C)** V oscillation shrinks (0.53×) under alternating transitions — Polyak (τ=0.005) damps the triad. **Hardening reco (non-blocking):** decorate `compute_g_realized` `@torch.no_grad()` — self-protecting regardless of caller + skips a throwaway graph (today the return-detach is the sole guard if a future refactor de-detaches). 4.7's `observe_value` scope extension is correct — **keep it.** Scale caveat: all probes at d=64 — re-verify reward-scale + divergence at production size; the F7b V-head-amplification half folds into #4 (de-risked by the encoder-half pass). **#3 signed off → proceed to #4.**

## 6. World model learns from lived experience  *(added 2026-06-23 by Brian)*
**What:** extend the seam so the JEPA **world model itself** (encoder + predictor) gradient-trains on lived Sanctuary transitions — predict the next latent, compare to the *realized* `s_next`, update the world model from that prediction error — not just the planner's value head (#3) and not just the corpus (today).
**Why:** today the world model's JEPA *gradient* training runs on the corpus; lived experience only changes it via living-weight self-modification and only *grounds the planner*. This closes the deeper goal — *the mind's model of reality learns from its actual life*, self-supervised (prediction error, no reward needed — the world is its own answer key). This is the sense of "the entity learns from experience" that #1–#5 don't yet deliver.
**Build (sketch — spec properly after #5):** in the seam learner, run the JEPA loss on the realized lived transition (context `s_t`/`a_t`, realized next-latent as the JEPA target) on the **core** optimizer, alongside but stop-grad-separated from the M9 head update. Reuses `JEPATrainer`'s machinery; the realized next-latent is already produced by the cycle. Preserve the M8/M9 two-optimizer split.
**Tightly coupled to:** **F8** (once the world model gradient-trains on lived data its θ moves every cycle, so the staleness machinery becomes genuinely live — no longer dormant) and the **async actor/learner** question (the 10 Hz cycle can't block on world-model gradient steps). #6 + F8 + async likely land together as the "live continual learning" sub-arc.
